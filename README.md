# HydroSense — สรุปงาน Hardware (อ่านไฟล์นี้ก่อน)

ระบบควบคุมการให้น้ำผักไฮโดรโปนิกส์ ใช้ ESP32 อ่านอุณหภูมิ ความชื้น และระดับน้ำ ส่งไปที่ Web API ทุก 5 วินาที แล้วสั่งปั๊มน้ำตามคำตอบที่ได้กลับมา

## ไฟล์ในโฟลเดอร์นี้
| ไฟล์ | ใช้ทำอะไร | ใครใช้ |
|---|---|---|
| `README.md` | สรุปภาพรวมและขั้นตอนถัดไป (ไฟล์นี้) | ทุกคน |
| `WIRING.md` | วิธีต่อสายทีละขาและชนิดของ Relay | น้องที่ต่อวงจร |
| `SETUP.md` | ติดตั้งโปรแกรม ตั้งค่า อัปโหลด และ API contract | น้องที่ต่อวงจร + คุณ (ฝั่งเว็บ) |
| `HydroSense/HydroSense.ino` | โค้ดที่อัปโหลดเข้า ESP32 | น้องที่ต่อวงจร |

## ภาพรวมการทำงาน
```
เซนเซอร์ (DHT22 + ลูกลอย)
        │
      ESP32 ──── POST JSON ───►  Web API ของคุณ
        │       {temperature, humidity, water_level}
        │                           │
        ◄──── {"pump_status": true/false} ────┘
        │
   Relay ──► ปั๊มน้ำ      LCD แสดงค่าทั้งหมด
```

## กฎความปลอดภัยที่ฝังไว้ในโค้ด
1. **น้ำหมด = ปั๊มต้องไม่ทำงาน** ตัดปั๊มทันที และปฏิเสธคำสั่งเปิดจากเซิร์ฟเวอร์
2. **ติดต่อเซิร์ฟเวอร์ไม่ได้เกิน 30 วินาที** ปั๊มจะปิดเอง
3. **ตอนเปิดเครื่อง** ปั๊มจะอยู่สถานะปิดเสมอ
4. **Wi-Fi หลุด** จะต่อใหม่เองทุก 10 วินาที

## ลำดับการทำงานทั้งหมด (เช็กลิสต์)

### ก. เตรียมของ (ใช้เวลาประมาณ 30 นาที)
- [ ] ติดตั้ง Arduino IDE 2.x
- [ ] เพิ่ม ESP32 Board Manager (SETUP.md ข้อ 1)
- [ ] ติดตั้ง Library ทั้ง 4 ตัว (SETUP.md ข้อ 2)
- [ ] ต่อ ESP32 เข้า USB แล้วเลือก Port ให้เจอ

### ข. ต่อวงจร **ยังไม่ต่อปั๊ม** (WIRING.md)
- [ ] ถอด USB ก่อนต่อสายทุกครั้ง
- [ ] ต่อ DHT22 → GPIO4 (ไฟ 3.3V)
- [ ] ต่อลูกลอย → GPIO27 กับ GND
- [ ] ต่อ LCD → GPIO21, GPIO22 (ไฟ 5V)
- [ ] ต่อ Relay → GPIO26 (ไฟ 5V)

### ค. ตั้งค่าและอัปโหลด
- [ ] เปิด `HydroSense.ino` แก้ SSID, รหัส Wi-Fi และ `API_ENDPOINT_URL`
- [ ] กด Verify (ติ๊กถูก) ให้ผ่านก่อน แล้วค่อยกด Upload
- [ ] เปิด Serial Monitor ที่ 115200

### ง. ทดสอบทีละขั้น (ผ่านทีละข้อก่อนไปข้อต่อไป)
| # | ทดสอบอะไร | ทำอย่างไร | ผลที่ถูกต้อง | ถ้าไม่ผ่าน |
|---|---|---|---|---|
| 1 | จอ LCD | เปิดเครื่อง | ขึ้น "HydroSense / Starting..." แล้วขึ้นค่า | ปรับสกรูคอนทราสต์หลังจอ / ลอง `LCD_ADDR = 0x3F` |
| 2 | DHT22 | เอามือกุมเซนเซอร์ | อุณหภูมิ/ความชื้นบนจอเปลี่ยน | เช็กสาย DATA และไฟ 3.3V |
| 3 | ลูกลอย | จุ่มน้ำ แล้วยกพ้นน้ำ | `W:OK` ตอนจุ่ม, `W:LOW` ตอนยก | ถ้าสลับกัน แก้ `FLOAT_CLOSED_MEANS_WATER_OK` |
| 4 | Relay | รัน Mock Server (SETUP.md ข้อ 6) ที่ตอบ `true` | Relay คลิก จอขึ้น `Pump:ON` | ถ้าติดทั้งที่ Pump:OFF แก้ `RELAY_ACTIVE_LOW` |
| 5 | **Dry-run** | ขณะ Pump:ON ยกลูกลอยพ้นน้ำ | Relay ดับทันที `Pump:OFF` แม้เซิร์ฟเวอร์ยังสั่ง `true` | **ห้ามต่อปั๊มจริงจนกว่าจะผ่านข้อนี้** |
| 6 | Wi-Fi หลุด | ปิด Router สักครู่แล้วเปิดใหม่ | ต่อกลับเอง และ Serial ขึ้น "[WiFi] เชื่อมต่อใหม่" | เช็ก SSID/รหัสผ่าน และ Wi-Fi ต้องเป็น 2.4GHz |
| 7 | Fail-safe | ขณะ Pump:ON ปิด Mock Server | ภายใน 30 วินาที ปั๊มปิดเอง | — |

### จ. ต่อปั๊มจริง (หลังผ่านครบทุกข้อ)
- [ ] ต่อปั๊มผ่าน COM + NO ของ Relay พร้อมไดโอดคร่อมปั๊ม (WIRING.md ข้อ 3)
- [ ] ทดสอบในภาชนะที่มีน้ำก่อน
- [ ] ทดสอบ Dry-run อีกรอบกับปั๊มจริง

## เราจะทำอะไรต่อ

### ฝั่งคุณ (Web)
1. **ทำ endpoint** `POST /api/hydrosense` ตาม API contract ใน SETUP.md ข้อ 5 รับ JSON แล้วตอบ `{"pump_status": true/false}` เริ่มจาก Mock Server ก่อนได้เลย
2. **ตัดสินใจกติกาสั่งปั๊ม** เช่น ปั๊มเปิดเมื่อไหร่ ปิดเมื่อไหร่ (ตั้งเวลา? ตามอุณหภูมิ? กดจากหน้าเว็บ?) ตอนนี้ฝั่ง ESP32 แค่ทำตามค่าที่ตอบกลับมา
3. **เก็บข้อมูลลงฐานข้อมูล** และทำหน้า Dashboard ดูค่าย้อนหลัง
4. **ถ้าจะขึ้นเซิร์ฟเวอร์จริง (HTTPS)** โค้ดตอนนี้ข้ามการตรวจใบรับรองไว้ (`setInsecure`) ควรเปลี่ยนเป็นตรวจใบรับรองจริงก่อนใช้งานจริง และควรเพิ่ม API key ในการส่งข้อมูล

### ฝั่งน้อง (Hardware)
1. ทำเช็กลิสต์ ก–จ ด้านบนตามลำดับ
2. ถ่ายรูปวงจรที่ต่อเสร็จและจดค่าที่ปรับเปลี่ยน (เช่น `LCD_ADDR`, ชนิด Relay) ส่งให้คุณเก็บไว้
3. ถ้าติดปัญหา ส่ง Log จาก Serial Monitor มาให้ ผมช่วยดูต่อได้

### ผมช่วยต่อได้
- เขียน endpoint ฝั่งเว็บ (บอกว่าใช้ภาษา/เฟรมเวิร์กอะไร)
- เพิ่ม API key, ปุ่มสั่งปั๊มด้วยมือ, หรือโหมดตั้งเวลาอัตโนมัติ
- เพิ่ม ESP32 โหมดเก็บค่าไว้ชั่วคราวถ้าอินเทอร์เน็ตหลุด
